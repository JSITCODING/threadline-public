# Threadline v0.1.0-rc.1

## English

This release candidate validates Threadline's first milestone with synthetic data. It is not yet approved for real conversation exports or personal vaults.

### Included

- Active-branch normalization for ChatGPT `conversations.json` exports.
- Explicit Portuguese and English Unicode coverage.
- Safe handling of missing attachment references and unsupported attachment shapes.
- Idempotent local SQLite imports.
- Manual, review-gated proposal flow with conflict detection, snapshots, audit, and rollback.
- Explicit Node.js type declarations across the TypeScript workspace.

### Safety boundary

- All committed fixtures and vault examples are synthetic.
- No provider is called implicitly.
- Applying a proposal requires explicit approval and an unchanged target hash.
- Absolute paths, traversal, unsafe symlinks, and writes outside the configured vault are rejected.

### Known limitations

- Sensitivity detection is a conservative heuristic, not a privacy guarantee.
- Real-export and real-vault pilots remain deferred.
- Candidate extraction, richer routing, and the React review interface are future milestones.

### Verification required before publication

- `pnpm check` and all eight tests pass locally.
- Tracked-file and full-history privacy scans are reviewed.
- Remote CI and Gitleaks pass on the release commit.

## Português

Este candidato a lançamento valida o primeiro marco do Threadline com dados sintéticos. Ainda não está aprovado para exportações reais de conversas nem para cofres pessoais.

### Incluído

- Normalização do ramo ativo em exportações `conversations.json` do ChatGPT.
- Cobertura explícita de texto Unicode em português e inglês.
- Tratamento seguro de referências a anexos ausentes e formatos de anexo não suportados.
- Importações idempotentes numa base de dados SQLite local.
- Fluxo manual de propostas, controlado por revisão, com deteção de conflitos, snapshots, auditoria e reversão.
- Declarações explícitas dos tipos do Node.js em todo o workspace TypeScript.

### Limites de segurança

- Todos os fixtures e exemplos de cofre versionados são sintéticos.
- Nenhum fornecedor é chamado implicitamente.
- A aplicação de uma proposta exige aprovação explícita e um hash do alvo que não tenha mudado.
- Caminhos absolutos, travessias, ligações simbólicas inseguras e escritas fora do cofre configurado são rejeitados.

### Limitações conhecidas

- A deteção de conteúdo sensível é uma heurística conservadora, não uma garantia de privacidade.
- Os pilotos com exportações e cofres reais continuam adiados.
- A extração de candidatos, o encaminhamento avançado e a interface React de revisão pertencem a marcos futuros.

### Verificação exigida antes da publicação

- `pnpm check` e os oito testes passam localmente.
- As verificações de privacidade dos ficheiros versionados e de todo o histórico são revistas.
- A CI remota e o Gitleaks passam no commit do lançamento.
